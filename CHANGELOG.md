# Changelog

## Unreleased

- **Background task checks while a dev server runs:** with an omp thread's dev server up, the task list asked omp for its services every 15 s, which starts a helper that takes about 0.4 s each time. It now asks only when a service starts, stops or changes, when its process has died, or every 5 minutes.
- **Browser pane lagging behind the window:** while an agent's page script or screenshot was waiting on a slow page (up to 10 s), the in-app browser's page stayed where it was when you resized the window, moved the divider or switched panels. The page now follows the pane straight away; agent commands on the page still run one at a time.
- **Slow usage refresh:** the Usage numbers refresh in under a second instead of about a minute when nothing new has happened. Every conversation that had saved agent or stream checkpoints was read again on each refresh, and the whole usage record was rewritten each time; now a conversation is read again only when it or its checkpoints change. Copies left behind by a refresh that was cut short are removed.
- **Slow thread list with long omp conversations:** listing a workspace's threads no longer rebuilds every saved conversation's whole history just to show its title. A workspace with 790 MB of omp sessions listed in 4.4 s instead of 25 s on first open, and in 2 ms afterwards until a conversation changes. Opening or sending in another thread of that workspace no longer waits for the listing to finish.
- **Computer Use errors that say what to do:** a run asked for more steps than Settings allows now gets the limit in the error ("from 1 to 30 …; ask for at most 30 or leave max_steps out") instead of "max_steps must be within configured limit". Keys refused because focus had left the app now say no keys were sent and to retry with a click on the field first, instead of "AX focused policy target belongs to another pid or cannot be read".
- **Dev servers stopped while you were away:** an omp thread left idle for 10 minutes was shut down even while a server the agent started (a bash call with a name) was still running, which took the server down with it. The agent then got "Supervised process … failed with exit code 143" the next time it started something, sometimes hours later, and lost its script cell's state. A thread now stays up while a process it started is running, and idles out once the process ends.
- **Script cells stopped mid browser call:** an omp eval cell that calls the in-app browser or Computer Use without its own timeout now gets 3 minutes (10 minutes with Computer Use) instead of 30 s. The browser call inside alone could take most of the 30 s, so the cell was stopped with the call still running and the kernel's state was lost. A timeout the agent sets is kept.
- **Browser tools that ran into the 30 s timeout:** every in-app browser tool now answers within 25 s. A call that runs out of time says so and what to check next, instead of the agent getting "Request timeout after 30000ms" with no idea what happened. A navigation that already landed stays a success when the page snapshot after it isn't ready in time. Browser calls sent together run side by side, so a slow one no longer holds back the calls behind it past their own timeout.
- **In-app browser stuck after a link to a section of the same page:** opening a URL that differs from the current page only after the # (for example `#market` to `#settings` in a one-page app) no longer leaves the page marked as loading for good. The agent's browser_navigate used to hang until the 30 s tool timeout, and every snapshot, screenshot or click after it waited for a load that never came.
- **Full access and nucode's own names:** a command no longer asks for approval because its text contains a lowercase "nucode_" (a tool name such as `mcp__nucode_browser`, a file name or a commit message). nucode's variables (`PI_CODING_AGENT_DIR`, `NUCODE_…`) now count only where a command reads, sets or clears them, and match by exact case as the shell does.
- **Fewer approval prompts in Full access:** a command that only reads (for example `grep`, `ls`, `find` or `cat`, piped together) no longer asks for approval because it mentions nucode's own settings, a `.git` folder or a variable such as `PI_CODING_AGENT_DIR`, for instance in a search pattern. A command that could change those (a redirect, `rm`, `find -delete`, setting the variable, or any `$` expansion) still asks.
- **Photo messages shown twice:** a message with a photo attached from a file showed twice in the conversation once the agent answered, although it was sent and saved once. The copy shown while sending held the file's path and the agent's copy the stored picture, so the two were never matched; they now are.
- **Turn times over an hour:** "Worked for" and the timers on background tasks and the session rail now show hours, so a two-hour turn reads "1:56:45" instead of "116:45".
- **Photos you drag in or pick:** a message with photos attached from files now sends. Before, it failed with "Request couldn't complete" and the photos were dropped, because the app tried to convert each file to inline data, which the desktop app refuses; the engine reads the files itself. Pasted images were not affected.
- **Browser on slow pages:** an agent can now click, type, scroll, read, take a snapshot or a screenshot on a page whose content is there but that is still loading images and ads, instead of waiting for the whole page to finish. A screenshot of such a page shows what is on screen now. If a page has not even started to show, the tools answer "still loading" within 15 seconds rather than hanging until the request times out.
- **Threads stuck on "Remove auth.json":** a thread no longer fails to start because an agent ran a `pi` command in its own shell. That command used nucode's private pi folder and left an empty `auth.json` in it; an empty file holds no account, so nucode now removes it and starts. A file with any content is still refused, since nucode does not support accounts or logins.
- **New thread:** the first message now shows in the conversation the moment you press Send, together with the Thinking row. Before, it appeared a few seconds later, after the runtime had been prepared and the thread started.
- **Screenshots an agent opens:** a picture an agent opens with its read tool now shows as a thumbnail in the tool row, with the tool's text as its output. Before, expanding the row printed the result as JSON: the whole picture as base64 text, or (since screenshots load on demand) a bare reference.
- **Opening a long conversation:** a conversation with hundreds of messages and dozens of screenshots (a synthetic one of 3,200 saved rows, 37 screenshots of 2-4 MB) opens in about a third of a second of engine time instead of about 15 seconds, and sends the window 18 MB instead of 346 MB. The window read the whole saved conversation again for every page of history it asked for, and sent every screenshot in full twice; it now reads it once and sends a reference for each screenshot, which it loads when the picture scrolls into view. The empty "What should we build?" screen no longer shows for a moment before "Loading…" when you open a conversation. Times are the engine's, from a release-speed test; the window's own share was not measured in the app.
- **Antigravity, OpenCode and Cursor:** all three can run a thread, next to pi and oh-my-pi. Turn one on in Settings → Engines; each shows whether its command-line tool was found, its version after Test, and how to install or sign in when it is missing. The tools sign in on their own: nucode never runs a login, opens a sign-in browser or gives them your provider keys, and a thread on one that is not signed in names the Terminal command to run (`agy`, `opencode auth login`, `cursor-agent login`). They bring their own models, so the model picker for their threads lists the agent's models (or "Agent default") instead of the provider list. Antigravity needs version 1.5 or newer, can be steered mid-turn, and shows "Antigravity quota exhausted" when its quota runs out; anything it adds after a turn ends stays in that turn. A stop the agent does not answer within 15 seconds restarts the agent so the next turn starts clean. Cursor support follows Cursor's documentation and has not been tried against the real tool.
- **Diffs keep their workers:** each diff in a thread started the shared diff worker pool, and closing the last one shut all eight workers down, so the next diff started them again and reloaded the highlighter. One app-wide pool now serves every diff, sized to half the CPU cores (2 to 6), and stops only after 30 seconds without a diff on screen (adapted from t3code, MIT).
- **One browser per thread:** the in-app browser kept one set of pages for every thread, so opening another thread's browser pane showed what the first thread's agent was doing, with its "Agent is using the browser" banner. Each thread now has its own pages: its agent sees and drives only those, and its pane, banner and Take over button show only that thread. Sign-ins are still shared, as in one browser with several windows. Codex and Claude threads still share one set of pages.
- **Streaming answers parse only what's new:** a streaming reply was re-parsed as Markdown from the start on every update. It now renders in blocks while it streams, so finished paragraphs are left alone and only the last block is parsed again (block splitter and incremental parser adapted from t3code, MIT). Completed messages render as before.
- **Terminal redraws no longer type junk:** switching terminal tabs or reopening the panel replayed the terminal's history while keystrokes were still forwarded to the shell, so old terminal queries in that history got answered and replies like `^[[?1;2c` could land at the prompt. Replays now send nothing to the shell, and query sequences are removed from replayed history (adapted from t3code, MIT).
- **Faster streaming in long threads:** every streamed token rebuilt every item in the thread as a new object, so each row re-rendered and re-parsed its Markdown on every token. Unchanged items now keep their identity and a user message's rewind control is passed as plain values, so only the row that changed renders. (Found while comparing with t3code.)
- **Screenshots in a reopened thread:** opening a thread that was still running reloaded its messages from the engine without turning saved image references back into images, so screenshots could show as a broken image. That reload now restores them like saved history does, and a tool image that still isn't real image data says "Image preview unavailable." instead of drawing a broken thumbnail.
- **Permissions survive rebuilds:** `sign-dev.sh` run from a worktree couldn't see `.signing-identity.local` and quietly signed the installed copy with "nucode Dev", and macOS ties Screen Recording, Accessibility and Keychain grants to the signer, so it asked again. The identity is now found from a worktree too (`scripts/signing-identity.sh`), `sign-dev.sh` warns when it falls back to "nucode Dev", and identities given as a certificate's SHA-1 are recognised by name for timestamps and notarization checks. Release artifacts still default to "nucode Dev", since a personal certificate puts its owner's name in the signature.
- **Computer Use says why it can't start:** when macOS withheld Screen Recording or Accessibility, runs said only "Grant Screen Recording and Accessibility in System Settings", even when System Settings showed nucode as allowed (an entry left from an earlier copy of the app). The message now names the missing permission and how to clear a stale entry. A background-mode screenshot whose first allowed app isn't running now names that app instead of "Target app is not running".
- **No stray "Unknown browser tab" note:** opening a thread whose saved browser tab still pointed at another thread's page asked to show that page, which the browser refused, and the refusal stayed on screen in every thread and project you opened after it. That tab is now dropped quietly, closing such a tab no longer asks the browser to close a page it can't touch, and a panel's error no longer follows you to another thread.
- **Access for threads started from a project page:** such a thread could run read-only while its composer showed Full access, so every command was refused. It now runs with the mode it shows. Choosing Ask first on a read-only thread now takes effect, and a refused command tells the agent why (read-only thread, read-only role, or a protected path) instead of listing all three.
- **Project page while a thread starts:** sending a prompt from a project's page no longer shows "Review in progress. Chat will re-enable when it completes." in the composer while the thread starts; it says "Starting the thread…".
- **Key presses inside frames:** when focus was inside a frame on the page, an agent's key press went to the frame's outer box and the page inside never saw it, so arrow-key checks of a map or list in a frame did nothing. Keys now go to the focused element inside the frame, as a real keyboard sends them.
- **Playwright selectors explained:** an agent that targets an element with Playwright syntax such as `text=Save` or `:has-text('Retry')` is now told that syntax isn't supported and to use a snapshot ref or plain CSS, instead of a bare "Invalid selector".
- **Agent pages that froze while nobody watched:** with the screen locked, the window covered, or the browser pane never opened, WebKit treated an agent's page as hidden and paused its animations and frame callbacks. Checks waiting on a frame timed out and panels stayed at their first keyframe. The agent's page now keeps running whether or not anyone is looking at it.
- **No approval card for leaving .git out:** in Full access, a command that names `.git` or `.env` only to exclude it (`rsync --exclude .git`, `grep --exclude-dir=.git`, `find . -name .git -prune -o …`) no longer stops the thread for approval. A command that could write into them still asks, now whatever the letter case.
- **Desktop widths in the in-app browser:** when an agent set a width wider than the pane, such as 1440 px, the page laid out at that width with text nearly twice its real size, so desktop checks showed overlaps a real window doesn't have. The page is now scaled down the way Safari's Responsive Design Mode does it, and text keeps its real size.
- **Browser left over the home screen:** going home or to another view at the moment the in-app browser was being moved could leave the page drawn on top of the new view until the app restarted. Moves and hides now reach the browser in the order they were made.
- **Browser at an agent-set width:** while an agent had narrowed the in-app browser to check a phone layout, a stretched copy of the page showed on both sides of it. The pane now draws only the page, centred.
- **Browser scripts that run too long:** an agent's script that runs past 10 seconds is now reported as timed out, with advice to split it, instead of "Native page did not respond; reload the tab" for a page that was fine.
- **Browser scripts cut off by a reload:** when a page reloads or navigates while an agent's script is running in it, the agent is now told that plainly, and what to do next, instead of getting WebKit's "Completion handler … no longer reachable".
- **Renames in Full access:** a rename through the language server (a symbol, or a file that stays in the project) no longer stops a Full access thread for approval, since Full access already edits project files unasked. Applying a code action still asks.
- **Edits judged by the files they change:** nucode's access rules now check every file an omp edit writes. Before, they looked at the project folder instead, so a subagent in Ask mode could edit files outside the project, including the thread's own access settings. Paths written in ways that move a file elsewhere (`~name`, a leading `:` or `@`, `[path#tag]`, odd spaces, file URLs) are judged as written to where they land or refused, and `.GIT`/`.ENV` are protected like `.git`/`.env`. A path starting `~/` in the file tools now means your home folder, as it already did in shell commands; before, reading `~/notes.md` failed.
- **Browser screenshots saved where the agent asked:** a screenshot taken with a filename is now written to that file (when the thread may write there) and the agent is told where; before, the filename was ignored and reports could cite screenshots that did not exist. The note after a key press now tells the agent how to check it worked instead of pointing at a setting it cannot change.
- **In-app browser stuck on "Unknown browser tab":** after an agent closed a page, the pane could keep that error and hide every page opened after it, so an agent seemed to work in the browser with nothing showing. Errors now belong to the page they happened on, and a page closing under the pane is not an error. nucode also no longer offers to save a login the agent typed.
- **False "Couldn't reach the provider" after a recovered turn:** a turn that hit a dropped connection and then carried on to the end no longer reopens as failed, with an error card under its final answer and its prompt put back in the composer.
- **Subagents off for a thread:** when a thread's team is turned off, agents no longer see a subagent tool they cannot use, and are told plainly that subagents are off. Before, they called it, were refused, and worked around it.
- **Read-only agents can run tests:** on macOS a read-only role, such as a reviewer in a council, can now run commands: tests, scripts, `git status`. Each command runs in a macOS sandbox where it can write only to its own temporary folder, cannot reach or look up anything beyond this computer, and cannot signal other processes, change preferences, use the clipboard, capture the screen, open files or apps, reach the keychain or start the tools that control other apps. Background jobs a command starts stop when it ends. Before, a read-only agent could only read files and run a few listing commands, so reviewers checked code by reading it. Tools that write caches into the project, such as Vite's config loader, fail in the sandbox (Vitest runs with `--configLoader runner`). A service already running on this computer (a build daemon, a local proxy, an SSH port forward) is outside the sandbox, and macOS still asks before an agent's script controls another app. Work's read-only roles are unchanged.
- **Choosing a model for an agent:** an agent asked to delegate to a model by its full registry name (for example `nucode-…/Claude Opus 5.5`) or by the model's id without the provider is no longer refused with "not enabled in the provider registry". The agent is told which models it can delegate to, and a model it cannot use is refused with that list. Before, an agent had to search nucode's internal settings files to find a name that worked.
- **Context window and auto-compact:** `/maxcontext 500k` sets the current model's context window (`/context-size` still works), and `/autocompact 290k` makes that model compact at that many tokens instead of at a percentage. The point has to stay below the window: a point at or above it is refused, and so is a window that would shrink to or below it. `/autocompact default` goes back to the default threshold, and `on`/`off` work as before. Both take effect on the thread's next message without a new conversation: the engine reloads and picks the same conversation up. The session rail's "Compact session" button is now a small filled button that stays on one line beside "… until auto-compact", at the end of the Context section. Refreshing a provider's models no longer clears a context window the provider does not report, and a slash command named in a reply (`/maxcontext`) is no longer shown as a file link.
- **Skills:** Settings → Skills makes your Claude Code, Codex and `~/.agents` skills available to every Code engine with one switch each, installs a skill pack from a GitHub address or a folder (for example `https://github.com/t3dotgg/tstack`), and turns individual skills on or off. Enabled skills reach pi, omp and Codex on their next start, and `$` in the composer lists them (`/skill:name` for pi and omp). omp still discovers nothing on its own: it loads only the skills you enabled.
- **Thread names:** with automatic titles off, a thread named after its first message no longer takes a greeting as its name. "Hi! Phase 3f is built, could you fix…" is now named "Phase 3f is built, could you fix…" instead of "Hi", and "Hi, on to the next phase" becomes "On to the next phase". Imported Claude Code sessions no longer take a background-task notice (`<task-notification>…`) as their preview.
- **Fewer round trips:** agents are now asked to request the files, line ranges and searches they already know they need in one step, and to read a range once rather than in consecutive pieces. In recorded runs four of five steps made a single tool call, each re-sending the whole conversation. When an agent still makes three single lookups in a row, the next request carries a one-line reminder to ask for the lookups it already knows together; the reminder comes at most once every ten steps.
- **Project commands use your home folder:** an agent's commands now run with your own HOME, while the engine keeps its separate settings folder. Before, each project's commands got a home folder of their own, so they rebuilt every Go, npm and bun cache per project (1.4 GB of caches plus 600 MB of Go modules in one project), could not find installed Playwright browsers and did not see your git identity. Read-only reviewers' sandboxed commands are unchanged.
- **Background tasks under a symlinked folder:** a background task or preview started from an engine folder whose path goes through a symlink (macOS `/var` is `/private/var`) ended at once with exit code 0 and ran nothing. The command guard now compares real paths, so it runs the command wherever the folder is.
- **No eval approvals in Full access:** with Full access, the engine's eval tool now runs without asking, like shell commands. Before, each new conversation stopped at an approval card for the first eval call and waited for an answer. Other access modes still ask for each call, and sub-agents still cannot use it.
- **UI checks you can watch:** agents now check pages in the in-app browser by default, so you can see what they look at. Headless browser scripts (Playwright, Puppeteer, Selenium) are for when you or the project's instructions ask for them; an agent that runs one anyway gets a one-line reminder. The project's own browser test suite still runs as usual.
- **Width chip in the browser:** when an agent sets the page to a phone or tablet width, the address bar shows that width; click it to fit the pane again.
- **Checking narrow layouts where you can see it:** agents can set the in-app browser to a phone or tablet width (browser_resize) and look at the page there. A width wider than the pane is scaled down to fit, and calling it with no width returns the browser to the pane's own size.
- **In-app browser after an agent closes a page:** the page's tab now goes away instead of staying as a dead "Unknown browser tab" with an empty address bar. Agents are also told to leave the page they checked open, so you can look at it after they finish, and a page that renders nothing now says so instead of returning an empty snapshot.
- **Role effort:** each agent role can have its own reasoning effort in the team editor and in Settings → Models & Agents → Roles, so a commander on Medium can run its team on High. A role without one uses the effort of the agent that delegates to it.
- **Chain of Command:** the composer's model chip shows a star while a team is on, and the team editor is large enough to show five roles with their models.
- **Agents opening the same pictures over and over:** an agent that keeps re-opening the same screenshots is now stopped even when it copies them to new folders or another format first. With a model reached through an OpenAI-format proxy, an agent can open at most two images per step: the proxy passes on only the last two, so a third is refused with that reason instead of arriving as text and being opened again.
- **Agents ending early:** an agent in a team no longer ends its run while a command it started in the background is still going (for example "waiting for the screenshots to finish", and then nothing). Agents now run their commands to the end before they reply, including ones that take longer than a minute, such as a full test suite.
- **Review reports:** a reviewer's report is no longer thrown away because it retyped a long acceptance criterion with different line breaks or spacing. A criterion can also be named by its number. A refused report now lists the criteria the reviewer was given (for example when it split them into more checks), or names the file to leave out, so the reviewer can correct it in one try.
- **Review:** a team turn that finishes its work no longer ends as a failed turn with "Review needs follow-up" when QA could not confirm a check. The turn completes, and a review card says how many checks were confirmed, names the ones that were not with QA's note, and offers "Check again with QA". A passed review shows as "Review passed". Turns that only read, search, use read-only roles or run commands that leave the project's files as they were no longer get a review status at all; before, any tool use in a team turn without a QA major ended it as failed. The card appears once, when the turn ends: a run that pauses for a background job and resumes no longer shows "Not reviewed" while it is still working. A review also stands through what cannot have undone it: a command after QA that changes no file (a status check, stopping a preview), and a run that resumes by itself after a background job. Before, either one ended the turn as "Not reviewed" although QA had run.
- **Agents:** a running agent shows what its latest step is doing and how many steps it has taken, in the Agents panel and on its row in the conversation ("designer · Viewing the alerts screen (step 12)"). Before, a delegation that ran for half an hour showed only a timer and a token count, so a working team looked stalled.
- **Agents going in circles:** an agent whose last 36 steps all repeat steps it has already made three or more times is told so in place of the next repeat, and asked to finish from what it has. A child agent that is told twice and still goes on loses its tools and has to report, so its parent is no longer left waiting on a run that will not end. Steps that differ only by a counter or an image format count as the same step; an edit with new text never counts as a repeat.
- **Long agent runs:** a Claude agent reached through a proxy no longer stops with a content filter error at the moment its history is first shortened to make room, and then again on every retry. The engine archives the older turns, the model's reasoning included, and sends the middle of a long archive as pictures of the text; Claude refuses a request that shows its reasoning back to it, as text or in a picture. nucode now takes the reasoning out of the turns before they are archived, and out of the text of archives made earlier. The archive's key to its labels no longer mentions the model's reasoning either: with that line alone, Claude refused a shortened history as soon as another message followed it, such as a finished background job's result.
- **Cut-off answers:** when a provider cuts an agent's answer off part-way (a content filter stop), the agent no longer fails and loses everything it did. It goes on from where it was, with its whole history, and is asked to write long results in smaller parts. This is tried twice; after that the agent ends with the provider's reason.
- **Context after a restart:** opening a conversation after the app restarts (or after a new build) shows its context usage straight away, taken from the saved conversation. Before, the Context section read "Usage not reported yet" until the next turn finished.
- **Model of a reopened conversation:** a conversation run on the OMP engine keeps its own model when it is opened after a restart. The engine records model changes in a different form from Pi, and reading it blanked the conversation's model, so the context capacity read "unknown" and the model had to be worked out again.
- **Approvals:** in a conversation with Full access, the approval for the engine's code-running tool (eval) now offers "Allow for session". One answer then covers that tool for the rest of the conversation, so a long turn no longer waits on the same question again and again. Other access modes and other tools ask each time, as before.
- **Send:** a message that cannot be sent because the conversation could not be started (the engine would not start) is no longer dropped without a word. A notice says why and the text goes back into the composer.
- **File links:** a path far outside the project is shown whole (`/tmp/notes/brief.md`) instead of as a climb to the root (`../../../tmp/notes/brief.md`). Nearby folders keep the short form.
- **Agent limit:** when a team turn runs out of agents, the conversation says how many it could not start and offers a higher per-turn limit in one click, sized for those agents plus a fix and a second check. The last agent a turn may start is now kept for a major, so the work can still be verified. The Agents view and the sub-agent row say "not started" for such an agent, with the reason, instead of an internal error.
- **Agents view:** once a conversation has started sub-agents, the title bar shows an Agents toggle that opens the tree of the team, with each agent's model, time and token use, and it stays after the run ends. Before, that view could only be opened from the browser pane's new tab. Previews of an agent's task and report no longer show Markdown marks. Run times read as minutes and seconds, and token counts as thousands or millions.
- **Sub-agents:** an expanded sub-agent row names each agent by role and number with its model, such as "Researcher 2: completed · Claude Haiku 5.5", instead of internal ids. The task and the agent's report read as formatted text instead of a raw code block, each agent's result is listed once, file paths in it keep their folder separator, and a call that started only some of its agents reads "Spawned 2 of 4" instead of "Spawn failed".
- **Context size:** `/context-size` and `/autocompact` take effect at once when sent during a running turn instead of waiting in the queue. Settings → Providers has a Context window field for each model, and each model's options fold into one row.
- **Project team:** saving a team for a project from the composer no longer copies the app's default engine and model onto the project, so the project keeps following the app when those change.
- **Agent tools:** `npm` and `npx` work in agent commands. They failed with a missing-module error, so agents fell back to whatever Node was installed on the Mac.
- **Composer:** reopening a conversation whose last turn ended with "Review needs follow-up", "Agent stopped unexpectedly" or "Interrupted when nucode closed" no longer puts the whole earlier request back in the composer. Those turns ask for a follow-up, not a resend.
- **Session panel:** with Git turned off in Settings → Features, the Environment section leaves the branch row out instead of saying "No Git branch" for a folder that has one.

## 0.8.2 — November 13, 2026

- **Settings:** every Settings page has a new layout: named groups, plain labels with one line of help, collapsed rows that show their current value, and a Save changes button on the pages that stage edits. Server, Browser, Models & Agents, Shortcuts and Projects were reorganized around what you are trying to do.
- **Attachments:** drag files from your file manager onto the composer to attach them. Images show as thumbnails above the message box instead of file names.
- **Scrolling:** you can scroll up through a conversation while a reply is being written. The view follows new text only when you are at the bottom.
- **Project menu:** right-click a project for Pin, Edit, Section, Reveal in Finder, Archive chats and Remove project. Remove project deletes the project's chats, checkpoints and engine data from nucode, and says so; the folder and its files stay on disk. Sections group projects in the sidebar under names you choose. Right-click a section's header to rename or delete it.
- **Thread menu:** right-click a thread for Rename, Pin, Mark as unread, Project, Section, Fork, Share, Copy, Open in new window, Archive and Permanently delete. Rename, Pin, Mark as unread and Archive have shortcuts you can change in Settings → Shortcuts. Moving a thread to another project and deleting it permanently work for pi and omp threads. The Copy items show a short notice naming what was copied, and Fork into a new worktree is left out when worktrees are turned off in Settings.
- **Thread windows:** Open in new window shows one thread in its own window, with its transcript and composer. It closes when the thread is archived or deleted and follows the thread when it moves.
- **Closed windows:** a closed thread, About or browser sign-in window is freed. Before, each one stayed behind as an invisible window until nucode quit.
- **Long titles:** a project or thread title too long for the sidebar scrolls to its end when you point at it.
- **Session rail:** the Context row at the top is gone. The Context section already shows how full the window is.
- **Dictation:** a keyboard shortcut that begins with the hold-to-talk key no longer starts a recording.
- **Dialogs:** the window behind a dialog is dimmed instead of blacked out.
- **Right-click:** an area with no menu of its own no longer shows the web view's Reload menu. Fields, links, pictures, the terminal and selected text keep theirs.
